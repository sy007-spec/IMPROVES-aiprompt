# FEATURE 1.1：完整特性

适用schema1；继承 [CONTRACT](../CONTRACT.md)。

## 输入与动作

所有主模板共享的正文规范。输入：一个特性的完整课程上下文、适用范围、角色、已知异常和证据。 允许整理、引用与提出待确认事项，不批准或发布。

## 提示词正文

按以下字段组织自然叙述，不要求七张表：

| 字母 | 字段 | 内容 |
|---|---|---|
| F | Frame | 场景、受众、问题、范围与不包含 |
| E | Experience | 触发、完整操作过程、结束条件 |
| A | Authority | 角色、数据范围、操作与审批权限 |
| T | Terms | 术语、状态、条件、规则及版本差异 |
| U | Unhappy paths | 失败、拒绝、撤销、超时、恢复与补偿 |
| R | References | 精确课程修订、跨特性依赖、冲突 |
| E | Evaluation | 有依据的验收条件与待确认事项 |

正文覆盖一个可完整解释的特性，必要规则可逐条表述但不拆掉上下文。原文没有的验收只能写为建议，不能宣称已批准。

## 输出与检查

返回符合本模板的编纂草稿，放入共同封套 artifacts。保留稳定ID及精确来源；缺项明确待确认，不为填满结构编造。检查事实/建议区分、权限/异常/适用版本完整、正文无重复、关系可解释。必要材料缺失或来源冲突无法判断时按 CONTRACT 停止相关定稿。

## 阅读、公式与流程规范

- 在文章前部、首次公式之前，用简短自然语言定义会影响理解的对象、重要术语和单位；读者不应先看到符号再到文末寻找解释。
- 优先用可直接读懂的中文名称或简短单词（如“分配比例”“本次分得利润”“管理费”），避免仅为缩短公式引入 ΔP、w、F 等字母或层叠下标。确有助于表达规律的符号可以保留，但必须先解释含义、范围和单位，全文保持一致。
- 公式采用 LaTeX 行内或独立公式块；中文名称用 `\text{名称}`，分式用 `\frac{分子}{分母}`，百分比用 `\%`。每步只解释一个计算目的，先写业务含义，再代入数值，最后解释结果。不要把 19/30 排版成 1930，不把公式截图作为权威正文。
- 示例说明假设、分母口径、时间范围与近似值；不因易读化改变结算、费用、尾差或权限规则。已有依据不支持的处理明确待确认。
- 流程属于章节上下文，按稳定流程 ID 关联完整特性；章节展示与全局汇总读取同一流程对象，支持双向定位。不另复制一套流程正文。没有必要时使用完整过程中的步骤叙述即可。
- Mermaid 图示必须使用完整的 mermaid 代码围栏，节点、连线及起止围栏齐全。跨章节引用完整图或稳定流程 ID，不截断到半条语句。渲染失败必须明确显示错误，不将代码假称为图形。
- 原始课程与修订不可改写；引文必须是原文连续片段，涉及图形时引用完整代码围栏。解释与简化在编纂正文中完成，和课程原文明确区分。
- 验收：逐个公式核对先定义、单位、数值和显示；逐图验证实际 SVG；章节到全局再回原章节可定位；窄屏无整页横向溢出。正文、引文、修订及问答引用使用一致的安全 Markdown/公式/图形渲染。

# 虚构示例：场地预约（SPINE）

仅演示格式。使用 [SPINE](../../templates/SPINE.md) 与 [FEATURE](../../templates/FEATURE.md)，继承 [CONTRACT](../../CONTRACT.md)。

## 输入材料

虚构来源 s-demo/c-booking/v1/r2 p1：“成员提交场地预约，管理员确认后预约生效；拒绝时告知原因。” p2：“生效前成员可以撤销申请。”

## 组织输出

Scenario：成员申请场地。Participants：成员、管理员。Intent：获得明确预约结果。Normal flow：提交 N1 → 等待确认 N2 → 生效 N3。Exceptions：N2拒绝→结束并告知原因；N2撤销→结束。并发抢占与生效后取消未提供，记缺口。

边E1：N1提交成功→N2；E2：管理员确认→N3；E3：拒绝→结束；E4：成员生效前撤销→结束。节点输入为申请，输出为待确认或最终状态；申请必填字段待确认。阶段引用同一F-01正文，不复制。

## F-01 完整特性草稿

Frame：成员预约场地，从提交到确认/拒绝/撤销。
Experience：提交后等待管理员决定；确认生效，拒绝告知原因。
Authority：成员提交和生效前撤销；管理员确认或拒绝；数据范围待确认。
Terms：申请状态与生效状态分离；确认后生效。
Unhappy paths：拒绝告知原因；生效前允许撤销；确认与撤销同时发生的结果待确认。
References：s-demo/c-booking/v1/r2 p1、p2；连续依据“生效前成员可以撤销申请”。
Evaluation：拒绝包含原因；生效前可撤销；不得把未给出的冲突解决规则视作已批准。

状态proposal。检查：有触发和终态，异常有出口，权限/并发缺口明确；这是业务模型，不是运行监控。

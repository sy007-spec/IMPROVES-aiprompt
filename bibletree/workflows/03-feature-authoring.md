# 编纂完整特性 1.1

继承 [CONTRACT](../CONTRACT.md)，按需加载 [FEATURE](../templates/FEATURE.md) 及书籍选定主模板。适用schema1，提示词提交由调用方固定。

## 输入

书籍范围、FEATURE、一个主模板、完整课程上下文、现有特性与稳定ID。

## 允许动作与提示词正文

仅分析、编纂草案或提出变更，不批准或部署。

围绕一个可完整理解和验收的产品特性编写。先核对与现有特性的重合，提出归并或引用，不机械按段落拆分。完整说明场景到结果，保留条件、权限、例外和版本差异；所有事实绑定证据。原子规则仅在有助阅读时附属列出。跨课程冲突原样说明，不自己确定正确一方。正文自然连贯，待确认集中但不得掩盖关键缺项。

## 输出格式

features/<id>.md草稿及引用、相关关系变更、gaps；新对象用临时ID。 使用CONTRACT共同封套，证据使用稳定来源标识与连续引文，未知字段显式标记。

## 停止条件与验收

必要材料、权限或当前基线缺失时停止相关定稿并列出缺项。逐项按FEATURE核验，包括文章前部的重要术语定义、可读公式、完整 Mermaid 图示及章节流程关联；不改来源、不自动保存或发布。 执行共同契约全部检查，未执行项如实列明。

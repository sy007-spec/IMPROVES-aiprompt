# 使用示例

以下内容均为虚构示例，不表示已经实施、测试或部署。

## 示例一：把模糊需求变成可验收任务

将以下信息填入 `PROMPT.md`，并同时提供 `IMPROVES.md`：

> 任务：为内部知识站设计访问申请流程。对象：员工与资料管理员。现状：暂无实际流程数据；“由管理员人工审批”是本次设计假设。成功标准：申请人能查询进度，未获授权者无法阅读受限资料。范围：只输出一期方案，不执行开发或发布。交付物：流程、权限、状态及验收清单。

合格输出应明确：谁能申请、谁审批、授权针对什么对象、批准或驳回后如何变化、重复申请如何处理、撤销授权何时生效，以及各实施项的责任角色与验收条件。未知审批时限应列为待确认，不能编造为现行制度。

验收准备应至少覆盖：正常批准、申请驳回、越权访问、重复申请、授权撤销，以及处理失败后的重试或恢复。此时状态应为“方案草案；实现未执行；测试未执行”。

## 示例二：审阅一句空泛计划

输入：“优化导出功能，提升体验。”

评审：缺少目标用户、实际问题证据、导出对象、权限、失败处理和成功标准，暂时无法验收。

可继续推进的写法：“先收集导出失败记录并确认影响对象；在取得数据后确定一期修复范围。拟由产品负责人确认范围、开发负责人提供修改、测试负责人验证正常导出、越权拒绝、空结果、容量边界与失败恢复。性能阈值和支持格式待确认，不预设为已批准要求。”

这一改写是行动建议，尚不构成批准的需求或实现承诺。

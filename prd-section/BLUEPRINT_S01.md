# BLUEPRINT-S01：PRD 分区功能规格提示词

一次写一个分区（功能模块）。质量底线见 [IMPROVES](../IMPROVES.md)，整份 PRD 骨架见 [BLUEPRINT](../BLUEPRINT.md)，输出骨架见 [TEMPLATE](TEMPLATE.md)。示例均为虚构。

## 0. 输入

| 输入 | 内容 | 缺失时 |
| --- | --- | --- |
| 分区卡 | 章节号、名称、所属层、FR 编号、负责人、目标版本 | 写“待补”，不得编造 |
| 原型 | 可运行页面或设计稿；可运行原型必须读代码（事件处理、状态变量、种子数据），不只看截图 | 写“无原型”，组件规格仅写已确认内容 |
| 上位 PRD | 范围（做／不做）、术语表、全局指标、需求总览 | 按原稿写，冲突入待确认 |
| 原稿与评审意见 | 已有分区草稿、会议结论 | 写“暂无” |
| 参考分区 | 同一 PRD 中已评审的高质量分区 | 只学结构与粒度，不复制其规则 |

**事实优先级**（冲突时正文按高者写，低者及冲突点入待确认）：

1. 用户最新决定 > 已定稿 PRD 正文 > 原型交互行为（代码）> 原型静态文案 > 原稿草稿 > 截图。
2. 范围（本期／延期／不做）以上位 PRD 为准；原型实现了 PRD 不做的功能时，照写规格但状态标“范围冲突”，并入待确认。
3. 原型种子数据是**演示数据**：人名、计数、样例条目只作示例，不写成初始数据；枚举（筛选取值、分类、档位、状态）可写为初始数据，标“来源：原型”。

## 1. 原型拆解（动笔前完成）

按页面逐项抽取，结果用于正文和第 6 节覆盖表：

| 抽取项 | 要得到什么 |
| --- | --- |
| 页面与入口 | 页面清单、导航入口、URL 参数、页面间跳转与传参 |
| 区域 | 每页按视觉顺序编号 A1、A2…，每区一句职责 |
| 交互元素 | 每个可点击／可输入元素：触发 → 状态变化 → 可见结果（含提示文案原文） |
| 状态变量 | 当前 Tab、筛选、搜索词、选中项、展开项、弹层开关；每个变量在什么操作下重置、保留 |
| 对象与字段 | 种子数据结构 → 业务对象与字段；计数如何得出 |
| 持久化 | 刷新后保留什么（URL、本地存储、服务端）；跨页带走什么 |
| 空态与异常 | 原型中的空态、提示、禁用条件原文 |
| 未实现 | 有按钮无处理、静态假数据、只切换样式的筛选：标“原型未实现”，入待确认 |

## 2. 九项内容 BLUEPRINT

| 字母 | 内容 | 合格线 |
| --- | --- | --- |
| B 业务目标 | 服务角色与场景；问题表；成功标准 | 问题表三列：问题｜现状痛点｜本分区的回答；成功标准写起点、终点、≤N 步、计步规则、一致性等式 |
| L 结构与层级 | 定位、域模型、Tab／页面划分、区域、术语、本期／延期、依赖 | 域模型写清每个对象的权威分区；共用模型只引用不重定义 |
| U 唯一路径 | 每个功能的起点、唯一入口、步骤与步数、权限 | 同一结果只有一条流程；跨分区动作（如“在对话中使用”）只写入口和交接数据，流程引用权威分区 |
| E 业务字段 | 每个组件的字段 | 字段表五列：字段｜来源｜展示格式｜出现条件｜空值 |
| P 权限与可见域 | 角色 × 动作；越权表现；敏感动作确认 | 越权表现三选一写明：不可见／置灰并说明原因／拒绝并提示；确认写文案、勾选项、默认值 |
| R 数据规则 | 搜索、排序、筛选、计数、去重、版本、初始数据 | 见第 3 节 R 细则 |
| I 交互联动 | 弹层、操作结果、按钮状态、加载、状态保留 | 见第 3 节 I 细则 |
| N 异常与存量 | 空态、失败、无权限、下架／旧版本、存量引用、重复提交 | 每种异常写：显示什么、保留什么、下一步动作 |
| T 可测可追溯 | 验收要点 | 第 4 节八维，每条可判定（数字、等式或明确状态） |

## 3. 细则

**R 数据规则**

- 搜索：范围（当前 Tab／全部）、匹配字段、触发时机（输入即搜；输入法组合输入结束后再检索）、清空方式、无结果后的返回位置。
- 排序：默认排序、可选排序、同值次序（如同值按 ID 升序），保证同一条件下顺序稳定。
- 筛选：维度表五列：维度｜取值｜默认｜每条目取值数｜是否后台配置；切换任一条件回到第 1 页。
- 计数：写成等式，如“Tab 计数 = 文件夹计数之和 + 收藏数”；写清何时 +1、何时不变（重复保存、取消、下架）。
- 重名与去重：同名对象的处理（拒绝并提示／自动改名“名称 (2)”）；重复保存不新增。
- 初始数据：中英文名、顺序、默认项；未确认的标“待确认”。
- 格式：数量（≥1 万显示“1.2w”）、时间（今天显示“HH:mm”，其他显示“M月D日”或相对时间，择一并全分区一致）、截断（行数与省略号）。

**I 交互联动**

- 弹层契约：入口、形态（抽屉／弹窗／下拉）、遮罩、关闭方式（关闭按钮、Esc、点遮罩）、关闭后恢复的状态清单、未保存内容的处理。
- 操作四段：操作 → 对象变化 → 计数变化 → 联动刷新。例：收藏 → 生成来源引用记录，不复制文件 → “我的收藏”+1 → 卡片显示“已收藏”，按钮变为“在个人库中查看”。
- 按钮状态矩阵：对象有两种以上状态时必须给矩阵（行：对象状态；列：用户状态或权限；格：按钮文案／可用性）。
- 状态保留表：每个状态变量在切 Tab、切筛选、关闭弹层、刷新页面、返回本页时是保留还是重置。
- 加载：首屏加载内容、分页或滚动加载、加载中占位；“刷新”按钮的作用范围。

**写法**

1. 先写“是什么、给谁、解决什么”，再写怎么做；整段描述改成表格或编号规则。
2. 文案、按钮名、提示语用「」引原型原文；建议改名写“原型「X」→ 建议「Y」”，并入待确认。
3. 每个组件独立写字段与文案，不沿用相邻组件的名称（如在单项详情里出现“组合包名称”）。
4. 规则只写一处：其他分区已定义的组件、流程、术语写“见 6.x.y”，不复制。
5. 禁用空话：“支持、优化、完善、友好、灵活、等、相关、以开发实现为准”不得代替规则；正文不留“❓、疑问、TODO”。
6. 原型与上位 PRD、原稿不一致处必须显式写出，不默默择一。
7. 截图仅示意；图文冲突以文字为准。

## 4. 验收八维

1. **计数一致**：各处计数满足 R 中的等式，保存、取消、删除后同步刷新。
2. **流程与步数**：起点到终点 ≤N 步；所有同类入口进入同一流程；重复操作不产生重复对象。
3. **筛选与分页**：切换条件回到第 1 页；列表、标题计数、分页一致；无结果有返回路径。
4. **状态恢复**：关闭弹层、取消操作后，状态保留表中的变量逐项恢复。
5. **失败恢复**：接口失败保留原内容并可重试；弹层内失败不关闭弹层；提交失败不丢输入。
6. **越权边界**：域外对象不可见；无权动作按 P 中写定的方式表现；敏感动作 100% 触发确认；已引用对象按引用时版本运行。
7. **可追溯**：对象 ID、版本、操作人、时间与任务轨迹可关联。
8. **空数据**：每个列表有空态文案与下一步动作；无意义字段显示“-”，不出现白屏。

## 5. 自检（不满足即修正，无法修正的入待确认）

- [ ] 第 1 节抽取的每个交互元素都出现在正文或覆盖表中
- [ ] 每个 Tab／页面有问题表、成功标准（含步数与等式）、区域编号、功能路径表
- [ ] 每个组件有五段：字段／操作与结果／数据规则／异常存量／联动与恢复，空段写“无”
- [ ] 两种以上状态的对象有按钮状态矩阵；每个弹层有关闭方式与恢复清单
- [ ] 计数、排序、筛选在正文与验收中口径相同
- [ ] 演示数据未写成初始数据；范围冲突已标注
- [ ] 无第 3 节禁用词；无跨分区复制的规则
- [ ] 待确认事项五列齐全；含“待补”或未清零待确认的分区不标“定稿”

## 6. 交付物

1. 分区正文（按 [TEMPLATE](TEMPLATE.md)）。
2. 待确认事项表：问题｜选项｜推荐｜负责人｜期限。
3. 原型覆盖表：元素｜页面／区域｜归属章节｜状态（已规格／引用 6.x.y／待确认／不做）。

符合本规范只说明文档写法合格，不代表需求已批准、设计已完成或功能已实现。
